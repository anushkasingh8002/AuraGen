# AuraGen WebSocket Protocol Specification

## 1. Message Envelope
All WebSocket communication between the client and server conforms to a standard JSON envelope:

```json
{
  "type": "string",
  "sessionId": "string",
  "payload": {}
}
```

- **`type`** (string, required): Event discriminator.
- **`sessionId`** (string, required): Unique identifier for the client session (generated by the client or server).
- **`payload`** (object | array, required): Event-specific data body.

Maximum allowed frame size is **64 KB** (`MAX_MESSAGE_BYTES = 64 * 1024`). Frames exceeding this size result in socket closure with code `1009` (Message Too Big).
The server accepts only the exact origins configured in `ALLOWED_ORIGINS`.
Each socket is limited to 100 messages per second.

## 2. Event Dictionary

### A. Lifecycle & Handshake

#### 1. `session:start` (Client $\rightarrow$ Server)
Initializes the session sliding window and registers the form ID.
```json
{
  "type": "session:start",
  "sessionId": "sess-live-98234",
  "payload": {
    "formId": "loan-application-v1",
    "section": "personal"
  }
}
```

#### 2. `session:ready` (Server $\rightarrow$ Client)
Acknowledges session creation.
```json
{
  "type": "session:ready",
  "sessionId": "sess-live-98234",
  "payload": {}
}
```

---

### B. Telemetry & Scoring

#### 3. `telemetry:batch` (Client $\rightarrow$ Server)
Batched stream of physical interaction events sent every 400–500ms.
```json
{
  "type": "telemetry:batch",
  "sessionId": "sess-live-98234",
  "payload": [
    { "k": "move", "v": 4.82, "t": 1700000000100 },
    { "k": "focus", "f": "monthlyIncome", "t": 1700000000000 },
    { "k": "click", "f": "monthlyIncome", "rage": true, "inert": false, "t": 1700000000250 },
    { "k": "error", "f": "monthlyIncome", "t": 1700000000300 }
  ]
}
```
- `k`: Event kind (`move`, `click`, `focus`, `blur`, `error`, `input`).
- `v`: Cursor speed in $\text{px}/\text{ms}$ (for `move` events).
- `f`: Field identifier being interacted with.
- `rage`: Boolean indicating $\ge 3$ rapid clicks within 600ms.
- `inert`: Boolean indicating clicks on elements with no state changes.
- `t`: Epoch millisecond timestamp.

#### 4. `score:update` (Server $\rightarrow$ Client)
Emitted when the Cognitive Load Score updates.
```json
{
  "type": "score:update",
  "sessionId": "sess-live-98234",
  "payload": {
    "score": 82,
    "parts": { "V": 0.85, "H": 0.90, "R": 1.0, "E": 0.50 }
  }
}
```

### C. DOM Snapshot & AI Redesign Flow

#### 5. `redesign:started` (Server $\rightarrow$ Client)
Notifies the browser that redesign generation has commenced.
```json
{
  "type": "redesign:started",
  "sessionId": "sess-live-98234",
  "payload": {
    "friction": {
      "field": "monthlyIncome",
      "score": 82
    }
  }
}
```

#### 6. `snapshot:request` (Server $\rightarrow$ Client)
Requests current DOM schema and entered values (timeout: 2,000ms).
```json
{
  "type": "snapshot:request",
  "sessionId": "sess-live-98234",
  "payload": {
    "requestId": "req-9843-abcd",
    "reason": "redesign"
  }
}
```

#### 7. `snapshot:response` (Client $\rightarrow$ Server)
Returns current form structure and flattened values.
```json
{
  "type": "snapshot:response",
  "sessionId": "sess-live-98234",
  "payload": {
    "requestId": "req-9843-abcd",
    "schema": {
      "formId": "loan-application-v1",
      "title": "Comprehensive Financial Loan Application",
      "fields": [
        { "id": "firstName", "label": "First Name", "type": "text", "required": true },
        { "id": "monthlyIncome", "label": "Monthly Net Income", "type": "number", "required": true }
      ]
    },
    "values": {
      "firstName": "Alice",
      "monthlyIncome": "45000"
    }
  }
}
```
Sensitive fields such as SSN are omitted from both schema and values; they stay
in the browser's original form state and are not included in redesign requests.

#### 8. `redesign:progress` (Server $\rightarrow$ Client, Optional)
Token generation progress (throttled to max once per 250ms).
```json
{
  "type": "redesign:progress",
  "sessionId": "sess-live-98234",
  "payload": {
    "tokens": 420
  }
}
```

#### 9. `redesign:ready` (Server $\rightarrow$ Client)
Delivers validated, compiled CommonJS component output. The browser treats
`code` as data only and does not evaluate it; it constructs its guided UI from
the safe form schema.
```json
{
  "type": "redesign:ready",
  "sessionId": "sess-live-98234",
  "payload": {
    "componentId": "fa81e4da6a0038e449aa0ffde6e016240886fffbab39f28938970abb9efd7c45",
    "version": 1,
    "code": "\"use strict\"; Object.defineProperty(exports, \"__esModule\", { value: true }); ...",
    "cached": false,
    "ms": 680
  }
}
```

#### 10. `redesign:failed` (Server $\rightarrow$ Client)
Emitted when generation or snapshot times out or fails.
```json
{
  "type": "redesign:failed",
  "sessionId": "sess-live-98234",
  "payload": {
    "reason": "snapshot_timeout"
  }
}
```

---

### D. Render Feedback & Submission

#### 11. `render:result` (Client $\rightarrow$ Server)
Reports whether client rendered the component or caught an error.
```json
{
  "type": "render:result",
  "sessionId": "sess-live-98234",
  "payload": {
    "ok": false,
    "componentId": "fa81e4da6a0038e449aa0ffde6e016240886fffbab39f28938970abb9efd7c45",
    "error": "TypeError: Cannot read properties of undefined"
  }
}
```
*Note: If `ok: false`, the server automatically evicts `componentId` from cache.*

#### 12. `wizard:submit` (Client $\rightarrow$ Server)
User submitted the completed simplified wizard.
```json
{
  "type": "wizard:submit",
  "sessionId": "sess-live-98234",
  "payload": {
    "firstName": "Alice",
    "monthlyIncome": "52000"
  }
}
```

#### 13. `submit:ack` (Server $\rightarrow$ Client)
Server confirmation of successful submission.
```json
{
  "type": "submit:ack",
  "sessionId": "sess-live-98234",
  "payload": {
    "ok": true
  }
}
```
